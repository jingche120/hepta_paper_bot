# v2 驗證說明

這份文件描述 v2 各模組的**規格與不變式**，用途是讓人或 AI 能獨立檢查實作是否正確。
它描述「應該如何」，不是「程式碼長什麼樣」——若兩者不符，以本文件為準或提出討論。

驗證範圍（分支 `feat/paper-pool`）：

| 模組 | 職責 | 對應測試 |
|---|---|---|
| `paper_pool.py` | 候選池：儲存、去重、評分、輪替選取 | `tests/test_paper_pool.py` |
| `openalex.py` | IEEE 期刊來源 | `tests/test_openalex.py` |
| `embeddings.py` | 向量計算（API 與本機兩種） | `tests/test_embeddings.py` |
| `backfill.py` | 一次性回填 CLI | `tests/test_backfill.py` |
| `executor.py` | 接線：ingest → 選取 → 寄信 | `tests/test_executor_pool.py` |

## 系統概觀

v1 的候選論文用完即丟：每天檢索、排序、寄信，然後全部丟棄。今天沒讀完的推薦明天就消失，
2022 年以來的相關論文也從未進入視野。

v2 把所有檢索到的論文存進 SQLite 池子，每天從**整個池子**挑選：

```
Heptabase 卡片 ──→ reading_history.json ──→ 質心向量 ─┐
                                                       │
arXiv 每日 ──┐                                        ▼
IEEE 期刊 ──┼──→ [ paper_pool.sqlite ] ──→ 評分 → 配額選取 → TLDR → 寄信
回填 2022~ ─┘            ↑                                    │
                          └──── 記錄推薦次數（輪替）←─────────┘
```

**比對基準永遠是使用者手寫的 Heptabase 卡片**，不是池中的論文。
池子只提供候選，不定義興趣。

# A. `paper_pool.py`

刻意**不連網**：embedding 由呼叫端算好傳進來。這讓整個模組能離線完整測試，
也讓 API 成本集中在一處管理。

## 資料表

```sql
papers(
  id TEXT PRIMARY KEY,        -- "arxiv:2211.14730" / "doi:10.1109/tgrs.2022.x"
  norm_title TEXT,            -- normalize_title(title)，跨來源去重用；無法正規化時為 NULL
  source TEXT NOT NULL,       -- arxiv | openalex
  title TEXT NOT NULL,
  abstract TEXT NOT NULL,     -- 唯一參與相似度計算的文字
  url TEXT,
  pdf_url TEXT,
  published_date TEXT,        -- ISO date；判斷新/舊，可為 NULL
  added_at TEXT NOT NULL,
  embedding BLOB,             -- float32 位元組；NULL 表示尚未計算
  embedding_model TEXT,
  recommend_count INTEGER NOT NULL DEFAULT 0,
  last_recommended_at TEXT,
  carded INTEGER NOT NULL DEFAULT 0   -- 1 = 已寫成 Heptabase 卡片
)
```

**三個欄位是累積狀態**，重新檢索到同一篇論文時不得被覆蓋：
`recommend_count`、`carded`、`embedding`。

## 不變式

### A1. 標題正規化要能跨來源比對

`normalize_title()` 對下列各組必須產生**相同**輸出：

| 情境 | 範例 |
|---|---|
| Unicode 連字號 vs ASCII | `Multi‐Station`(U+2010) ≡ `Multi-Station`(U+002D) |
| 各種破折號 | U+2010 U+2011 U+2012 U+2013 U+2014 U+2015 U+2212 U+FF0D |
| 大小寫、標點、空白 | `A Study: Part I` ≡ `a study, part i` |
| 連字號 vs 空白 | `multi-station` ≡ `Multi Station` |

**為什麼重要**：使用者卡片上的
`EdgePhase: A Deep Learning Model for Multi‐Station Seismic Phase Picking`
用的是 U+2010，而 arXiv 與 OpenAlex 用 ASCII。比對失敗會導致**已讀論文被重複推薦**。

CJK 須保留（卡片標題可能是中文）。空字串與 `None` 回傳 `""`。

### A2. 重複 ingest 不得覆蓋累積狀態

同一 `id` 再次 ingest：不新增列、`skipped_id` 增加，
且 `recommend_count`、`carded`、`embedding` 維持原值。

### A3. 去重必須由資料庫保證

`norm_title` 上有 **UNIQUE 索引**，寫入用 `INSERT ... ON CONFLICT DO NOTHING`。

「先查再寫」不是原子操作：兩個程序同時 ingest 時（回填跑到一半、每日任務剛好觸發）
會讓同一篇論文的兩個版本都進池。`id` 不同但標題相同的情況是真實存在的——
同一篇論文的 arXiv 預印本與 IEEE 正式版。

標題無法正規化者存 **NULL**；SQLite 的 UNIQUE 允許多個 NULL，因此彼此不互撞。

### A3b. 舊資料庫必須真的被升級

`CREATE UNIQUE INDEX IF NOT EXISTS` **只看名稱存不存在，不看 UNIQUE 旗標**。
早期版本建的 `idx_papers_norm_title` 是非 UNIQUE 的，同名，於是既有資料庫會靜默
沿用舊索引——A3 的保證形同虛設，而且沒有任何錯誤訊息。同期的 `norm_title` 還是
`NOT NULL`，無法正規化的標題會直接寫入失敗。

`PaperPool._migrate()` 因此必須：

| # | 不變式 |
|---|---|
| a | 開啟舊資料庫後，`PRAGMA index_list(papers)` 的 `idx_papers_norm_title` 必須是 UNIQUE |
| b | 升級後 `norm_title` 允許 NULL（無法正規化的標題可以寫入） |
| c | 用**現行**的 `normalize_title()` 重算所有 norm_title——舊版規則保留連字號與空白，舊值與新算法對不起來，比對已讀卡片會失敗 |
| d | 建 UNIQUE 索引前要先解決既有重複，保留狀態最完整的一筆（已寫成卡片 > 推薦過 > 已有向量 > 先進池的），並回報刪掉哪些 id |
| e | `recommend_count`、`carded`、`embedding`、`embedding_model` 必須完整保留 |
| f | 已是現行 schema 的資料庫重複開啟時不做任何事（冪等） |


### A4. 只有缺向量或模型過期的才需重算

`pending_embeddings(model)` 只回傳 `embedding IS NULL` 或 `embedding_model != model` 的列。

**為什麼重要**：這是成本控制關鍵。少了這道過濾，每天會重算整個池子
（19,200 篇 ≈ $0.15/天 ≈ $4.5/月，而非 $0.1/月）。

### A5. 沒比對到的卡片要被回報

`mark_carded()` 回傳「沒有比對到任何池中論文」的卡片標題清單，不得靜默略過。

**為什麼重要**：卡片的 `來源論文：` 有時不是論文名（指向 arXiv 查詢網址時，
標題會變成中文的「論文總覽：PatchTST」）。這種卡片對應的論文會被當成未讀而重複推薦。

### A6. 向量必須是單位長度

分數 `(向量 · 質心) × 10` 只有在雙方都經 L2 正規化時才等於餘弦相似度。
例如兩個 `[2, 0]` 向量會得到 40，但餘弦分數應是 10。

`store_embeddings()` 與 `weighted_centroid()` 都在內部強制正規化，
讓前提由結構保證，而非依賴呼叫端傳入正規化過的向量。零向量拋 `ValueError`。

**非有限值同樣要拒絕。** `[inf, 0]` 的範數是 `inf`，`inf / inf` 得到 `NaN`，
NaN 會被寫進資料庫，一路傳到 `select()` 的分數，讓排序變成沒有意義的亂序
**而且不報錯**。因此 `_l2_normalize()` 在計算範數前先要求所有元素有限。

### A7. 選取行為

| # | 不變式 |
|---|---|
| a | `carded = 1` 的論文**永不**出現在 `select()` 結果 |
| b | 回傳數量 = `min(n_new, 可用新論文數) + min(n_old, 可用舊論文數)` |
| c | 新舊分界：`published_date >= today - new_within_days` 為「新」；**邊界值算新**；`published_date` 為 NULL 者歸「舊」 |
| d | 排序鍵為 `(recommend_count ASC, score DESC)` |
| e | `embedding IS NULL` 的論文不參與選取 |
| f | 空池回傳 `[]`；配額為 0 要被遵守；負配額拋 `ValueError` |
| g | 質心維度與池中向量不符時拋 `PaperPoolError` |
| h | 池中混用多個 `embedding_model` 時拋 `PaperPoolError`；`select(model=...)` 可指定只用某個模型 |

**h 為什麼重要**：不同模型的向量不可比。維度相同時混用**不會有任何錯誤**，
只會靜默給出無意義的排名。

### A8. 輪替與推薦計數

- `mark_recommended()` 使 `recommend_count` **恰好 +1**，並更新 `last_recommended_at`。
- 同一次呼叫中重複出現的 id **只計一次**（重複計數會把該篇錯誤地推到隊伍更後方）。
- 連續兩次 `select()`（中間呼叫 `mark_recommended`）選出的清單**不同**。
  註：可用論文數 ≤ 配額時必然相同，這是該性質的邏輯前提，非缺陷。

**輪替的意義**：推薦過的論文排到隊伍後方，等其他高分論文輪過一遍才再出現。
因此不會連續多天重複同一篇，但也沒有論文會被永久丟棄——只有寫成卡片才會被排除。

### A9. 寫入不存在的 id 要出聲

`store_embeddings()` 與 `mark_recommended()` 對不在池中的 id 拋 `PaperPoolError`，
而非靜默更新零列。靜默忽略會讓該篇永遠留在 `pending_embeddings()` 裡，
每次執行都重算一次向量。

### A9b. 未知 id 必須讓整批回滾

`store_embeddings()` 的 `PaperPoolError` 必須在 `with self._conn:` **之內**拋出。
若等離開區塊再拋，有效的那幾筆已經 commit，錯誤訊息卻讓呼叫端以為整批都沒寫入——
這正違反「中途失敗不留下半寫入狀態」。

驗收：同一批傳入一個已存在的 id 與一個不存在的 id，拋錯後前者的 embedding
必須仍是 `NULL`。

### A10. 分數與既有公式等價

分數 = `(論文向量 · 質心向量) × 10`，必須與
`src/zotero_arxiv_daily/reranker/base.py` 的
「對每篇閱讀紀錄各算餘弦相似度，依時間衰減權重加權平均，再乘以 10」**數值等價**，
因為內積是線性的：

$$\sum_i w_i (c \cdot h_i) = c \cdot \left(\sum_i w_i h_i\right)$$

用質心可少算 `len(history)` 倍的乘法。時間衰減權重為
`1 / (1 + log10(rank + 1))` 正規化後的值，順序由**新到舊**，總和為 1。

# B. `openalex.py`

IEEE TGRS 與 GRSL 不在 arXiv 上，IEEE Xplore 的 API 需要訂閱。
OpenAlex 免費、不需金鑰，這兩本期刊摘要覆蓋率實測 100%（各抽樣 100 篇）。

### B1. 摘要是 inverted index，必須還原

OpenAlex 的 `abstract_inverted_index` 形如 `{詞: [位置, ...]}`。
還原時要依位置排序，且**重複出現的詞要在每個位置都出現**。
缺摘要或空 index 回傳 `None`。

### B2. 每日增量只能用 `publication_date`，並對齊年初

OpenAlex 的 `from_created_date` 與 `from_updated_date` **需要付費方案**。
免費金鑰收到 HTTP 429 加上 `{"error":"Plan upgrade required"}`——狀態碼看起來像
速率限制，實際不是，很容易誤判成重試就會好。

而 IEEE 的 `publication_date` 是期號日期，粒度是「年」（2026 年的論文全部標成
`2026-01-01`），所以 `from_publication_date:yesterday` 回傳 0 筆且不報錯。

兩條路都堵住，因此每日作法是**重抓整個當年度**，靠候選池去重：

| # | 不變式 |
|---|---|
| a | `fetch_works()` 只送 `publication_date` 過濾；不得出現 `created_date` 或 `updated_date` |
| b | `publication_window_start(today, lookback_days)` 回傳 `today - lookback_days` **所在年份的 1 月 1 日**，不是那一天本身 |
| c | 跨年時視窗要同時涵蓋前一年（`2027-01-10` 往回 30 天 → `2026-01-01`） |
| d | 重複執行不得產生重複資料——第二次 ingest 的 `inserted` 為 0 |

實測成本：TGRS 2026 年 1,928 篇（10 次請求）、GRSL 660 篇（4 次請求），
合計每天約 14 次請求。

### B3. 識別碼以 DOI 為主

有 DOI 時 id 為 `doi:<小寫 DOI>`（同一篇論文在不同來源要得到相同 id），
否則退回 `openalex:<W...>`。缺標題、缺摘要、或兩種 id 都拿不到的紀錄一律略過。

### B4. 分頁

cursor 分頁，起始為 `*`，以 `meta.next_cursor` 前進。
`next_cursor` 為 `None` 或該頁為空時停止。
**游標未前進時必須拋錯**，否則會無限迴圈。

# C. `embeddings.py`

回填與每日流程共用，避免批次大小、截斷規則、錯誤處理在兩邊各自演化。

### C1. 回傳必須完整，不只是排序

API **不保證**回傳順序與請求順序相同，因此必須依 `index` 排回原序。
但**只排序不夠**：少回一筆、index 重複或缺號時，`zip(chunk, vectors)` 會靜默截斷，
把向量配到**錯的論文**上。錯誤的向量就此永久存進池子，之後每天都用它評分，
而且不會有任何錯誤訊息。

| # | 不變式 |
|---|---|
| a | 回傳的 index 集合必須恰好是 `0..n-1`；缺號、重複、超出範圍或數量不符一律拋 `EmbeddingResponseError` |
| b | 完整但亂序的回應要能正確排回原序 |
| c | `embed_pending()` 另外檢查 embedder 回傳的向量數等於這批的論文數（涵蓋本機 embedder） |
| d | 檢查失敗時該批**不得**有任何向量被寫入池中 |

### C2. 只算缺向量的

`embed_pending()` 只處理 `pool.pending_embeddings(model)` 回傳的列。
第二次執行對相同模型**不得產生任何 API 呼叫**。換模型則全部重算。

### C3. 本機模型要有命名空間

`LocalEmbedder.model` 前綴 `local:`，避免與同名的 API 模型在池中被誤認為同一種向量。

### C4. `get_embedder()` 沿用既有設定鍵

依 `executor.reranker`（`api` / `local`）建立，不新增設定鍵，
讓 README 既有說明維持正確。未知值拋 `ValueError`。

# D. `backfill.py`

### D1. 分季不得有空隙或重疊

`quarter_starts(start, end)` 產出的區間必須**首尾相接**（前段結束日 +1 天 = 次段起始日）、
不重疊，且完整覆蓋 `[start, end]`（第一段起始 = `start`，最後一段結束 = `end`）。
`start > end` 回傳空清單。跨年邊界要正確。

**為什麼分段**：arXiv 單次查詢有結果數上限，一次抓四年會被截斷。

### D2. 中斷後重跑不得產生重複

回填是長時間作業。重跑時已存在的論文由池子去重跳過，只寫入新的。
`recommend_count` 等狀態在重新開啟資料庫後必須保留。

### D3. 每一段各自成為一個交易

`pool.ingest()` 內部是一個交易。若把所有季度包進同一次 `ingest()`，第十季下載失敗
會連前九季一起回滾，整趟回填白跑——正好違背 D2 的「中斷後重跑」設計。

驗收：讓第三季拋錯，前兩季的論文必須仍留在池中。期刊同理，逐本各自 ingest。

### D4. `--until` 必須套用到兩種來源

`--until` 只套到 arXiv 的話，期刊會一路抓到現在，與使用者指定的區間不符。

未指定 `--until` 時**不得**拿今天當上限傳給 OpenAlex：IEEE 的 `publication_date`
是期號日期，可能落在未來，用今天封頂會靜默漏掉這些論文。

# E. `executor.py` 接線

### E1. 每日論文要存進池子

`ingest_daily_sources()` 把當日 arXiv 論文與 IEEE 期刊增量寫入池子，
而不是排序完就丟。**必須帶上 `published_date`**，否則所有論文都會被歸為「舊」，
`n_new` 配額形同虛設。

### E2. 閱讀紀錄要由新到舊排序後才算質心

`time_decay_weights` 假設順序是新到舊。閱讀紀錄從檔案讀出時是**舊到新**，
不排序會讓**最舊的卡片拿到最高權重**——與設計意圖完全相反。

### E3. embedding 用的是 embedding 憑證

embedding 走 `reranker.api.*`（`EMBEDDING_*` 環境變數），
與 LLM 的 `llm.api.*`（`OPENAI_*`）是分開的。不可把 LLM 的 client 直接拿來算 embedding。

### E4. 寄信成功才計入推薦次數

`mark_recommended()` 必須在 `send_email()` 之後。先計次的話，
寄信失敗會讓這些論文白白排到隊伍後方，下次不會再被選中。

`dry_run` 為真時：印出選中的論文，**不寄信、也不計次**。

### E5. 沒有 retriever 的來源不得崩潰

IEEE 期刊有付費牆、沒有對應的 retriever。`fetch_full_texts()` 遇到這種來源
應保持 `full_text` 為 `None`（TLDR 會自動回退成摘要），而不是拋 `KeyError`。

### E6. 池中舊論文仍要能抓全文

`fetch_full_text()` 原本依賴當次檢索的 `_raw_by_url` 快取，
但池中的舊論文是先前執行檢索到的，不在快取裡。
必須能從儲存的 abs 網址推導 arXiv 來源網址。

# 測試品質要求

測試必須**真的能抓到錯誤**，不能只是走過流程。以下突變植入後，測試套件必須失敗：

| 植入的錯誤 | 對應不變式 |
|---|---|
| `normalize_title` 改成 `title.lower()` | A1 |
| `_l2_normalize` 直接回傳原向量 | A6 |
| `norm_title` 索引改成非 UNIQUE | A3 |
| `ingest` 拿掉 `norm_title` 去重 | A3 |
| `ingest` 改成每列立即 commit | 交易邊界 |
| `pending_embeddings` 回傳全部列 | A4 |
| `select` 拿掉 `carded = 0` 過濾 | A7a |
| `select` 不擋混用 embedding 模型 | A7h |
| `recommend_count + 1` 改成 `= 1` | A8 |
| `mark_recommended` 不去除重複 id | A8 |
| `store_embeddings` 對未知 id 靜默忽略 | A9 |
| `embed_texts` 不依 index 排序回傳 | C1 |
| executor 不把閱讀紀錄排成新到舊 | E2 |
| executor 在寄信前就 `mark_recommended` | E4 |
| `_l2_normalize` 不擋 NaN / Infinity | A6 |
| `_migrate()` 直接回傳空清單（不升級舊資料庫） | A3b |
| `_migrate()` 不重算 `norm_title` | A3b-c |
| 重複標題保留最後一筆，而非狀態最完整的那筆 | A3b-d |
| `store_embeddings` 的 `PaperPoolError` 移到交易外 | A9b |
| `embed_texts` 只排序、不驗證 index 完整性 | C1a |
| `embed_pending` 不檢查向量數量 | C1c |
| `backfill_journals` 丟掉 `until_date` | D4 |
| `backfill_arxiv` 把所有季度合成單一交易 | D3 |
| `publication_window_start` 回傳當天而非年初 | B2b |
| `fetch_works` 送出 `from_created_date` | B2a |
| executor 改成 `get_embedder(config, self.openai_client)` | E3 |
| 移除 `fetch_full_text` 的 `_arxiv_ref` 網址回退 | E6 |

其他要求：全部離線（不連網、不呼叫 API、不下載模型）；向量用固定亂數種子。

# 一般性檢查

- SQL 一律參數化，不得字串拼接
- 寫入操作要有交易邊界，中途失敗不留下半寫入狀態
- 例外不得被吞掉而讓資料靜默損壞

# 已知限制（屬預期行為，非缺陷）

- **IEEE 論文永遠落在「舊」那一側**，因為 `publication_date` 是期號日期。
  `n_new` 的名額實務上都由 arXiv 當日論文取得。
- **IEEE 論文抓不到全文**（付費牆），`full_text` 為 `None`，TLDR 回退成摘要。
- **`論文總覽：PatchTST` 卡片比對不到任何論文**，因為它的 `來源論文：`
  指向 arXiv 查詢網址。`mark_carded()` 會回報它。修卡片即可解決。
- **只有 `abstract` 參與相似度計算**，`title` 不參與計分。
- 相似度採全部閱讀紀錄的加權平均（非 max 或 top-k），
  多主題閱讀紀錄會有質心稀釋效應——這是明確選擇的取捨。
- arXiv 論文的 id 含版本號（`2211.14730v1`），同一篇的不同版本 id 不同，
  靠 `norm_title` 去重。
- **升級舊資料庫時會刪除重複標題的列**（同一篇論文的另一個版本），保留狀態最完整的一筆。
  刪掉的 id 會寫進 log。這是建立 UNIQUE 索引的必要前提。
- **期刊每天重抓整個當年度**（約 14 次請求），因為免費方案沒有任何「最近新增」的
  過濾條件可用。寫入量仍然很小——池子只會收下真正新增的那幾篇。
