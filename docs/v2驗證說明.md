# v2 驗證說明：候選池 `paper_pool.py`

這份文件描述 `paper_pool.py` 的**規格與不變式**，用途是讓人或 AI 能獨立檢查實作是否正確。
它描述「應該如何」，不是「程式碼長什麼樣」——若兩者不符，以本文件為準或提出討論。

## 這個模組在整個系統的位置

```
Heptabase 白板卡片 ──→ reading_history.json ──┐
                                              ├─→ 質心向量 ─┐
arXiv / OpenAlex ──→ [ paper_pool ] ──────────┘             │
                          ↑                                  │
                          └────── select() ←─────────────────┘
                                     ↓
                          每天 3 篇 → TLDR → 寄信
```

v1 的候選論文用完即丟，今天沒讀完的推薦明天就消失。v2 把所有檢索到的論文存進池子，
每天從**整個池子**挑選，因此老論文也有機會被推薦，沒被選上的也不會遺失。

`paper_pool.py` **刻意不連網**：embedding 由呼叫端算好傳進來。
這讓整個模組能離線完整測試，也讓 API 成本集中在一處管理。

## 資料表

```sql
papers(
  id TEXT PRIMARY KEY,        -- "arxiv:2211.14730" / "doi:10.1109/TGRS.2022.x"
  norm_title TEXT NOT NULL,   -- normalize_title(title)，跨來源去重用
  source TEXT NOT NULL,       -- arxiv | openalex
  title TEXT NOT NULL,
  abstract TEXT NOT NULL,     -- 唯一參與相似度計算的文字
  url TEXT,
  pdf_url TEXT,
  published_date TEXT,        -- ISO date；判斷「新/舊」用，可為 NULL
  added_at TEXT NOT NULL,     -- 進入池子的時間
  embedding BLOB,             -- float32 位元組；NULL 表示尚未計算
  embedding_model TEXT,       -- 換模型時據此判斷需重算
  recommend_count INTEGER NOT NULL DEFAULT 0,
  last_recommended_at TEXT,
  carded INTEGER NOT NULL DEFAULT 0   -- 1 = 已寫成 Heptabase 卡片
)
```

**三個欄位是累積狀態**，重新檢索到同一篇論文時不得被覆蓋：
`recommend_count`、`carded`、`embedding`。

## 不變式

以下每一條都應有對應測試。括號內是測試類別。

### 1. 標題正規化要能跨來源比對（`NormalizeTitleTests`）

`normalize_title()` 對下列各組必須產生**相同**輸出：

| 情境 | 範例 |
|---|---|
| Unicode 連字號 vs ASCII | `Multi‐Station`(U+2010) ≡ `Multi-Station`(U+002D) |
| 各種破折號 | U+2010 U+2011 U+2012 U+2013 U+2014 U+2015 U+2212 U+FF0D |
| 大小寫、標點、空白 | `A Study: Part I` ≡ `a study, part i` |
| 連字號 vs 空白 | `multi-station` ≡ `Multi Station` |

**為什麼重要**：使用者卡片上的標題
`EdgePhase: A Deep Learning Model for Multi‐Station Seismic Phase Picking`
用的是 U+2010，而 arXiv 與 OpenAlex 用 ASCII。比對失敗會導致**已讀論文被重複推薦**。

CJK 字元須保留（卡片標題可能是中文）。空字串與 `None` 回傳 `""`。

### 2. 重複 ingest 不得覆蓋累積狀態（`IngestDedupTests`）

同一 `id` 再次 ingest 時：不新增列、`inserted` 不增加、`skipped_id` 增加，
且 `recommend_count`、`carded`、`embedding` 維持原值。

### 3. 相同正規化標題視為同一篇（`IngestDedupTests`）

`id` 不同但 `norm_title` 相同時（同一篇論文的 arXiv 預印本與 IEEE 正式版），
只保留先寫入的那筆，`skipped_title` 增加。標題真的不同的論文則都要寫入。

### 4. 只有缺向量或模型過期的才需重算（`PendingEmbeddingTests`）

`pending_embeddings(model)` 只回傳
`embedding IS NULL` 或 `embedding_model` 不等於 `model` 的列。

**為什麼重要**：這是成本控制的關鍵。少了這道過濾，每天會重算整個池子
（19,200 篇 ≈ $0.15/天 ≈ $4.5/月）。有了它，每天只算新進的數十篇，成本趨近於零。

### 5. 沒比對到的卡片要被回報（`MarkCardedTests`）

`mark_carded()` 回傳「沒有比對到任何池中論文」的卡片標題清單，不得靜默略過。

**為什麼重要**：卡片的 `來源論文：` 有時不是論文名（指向 arXiv 查詢網址時，
標題會變成中文的「論文總覽：PatchTST」）。這種卡片對應的論文會被當成未讀而重複推薦，
使用者需要知道是哪幾張卡片要修。

### 6–12. 選取行為（`SelectTests`）

| # | 不變式 |
|---|---|
| 6 | `carded = 1` 的論文**永不**出現在 `select()` 結果 |
| 7 | 回傳數量 = `min(n_new, 可用新論文數) + min(n_old, 可用舊論文數)` |
| 8 | 新舊分界：`published_date >= today - new_within_days` 為「新」；**邊界值算新**；`published_date` 為 NULL 者一律歸「舊」 |
| 9 | 排序鍵為 `(recommend_count ASC, score DESC)` |
| 10 | `mark_recommended()` 使 `recommend_count` **恰好 +1**，並更新 `last_recommended_at` |
| 11 | 連續兩次 `select()`（中間呼叫 `mark_recommended`）選出的清單**不同**——輪替生效 |
| 12 | `embedding IS NULL` 的論文不參與 `select()` |

其他邊界：空池回傳 `[]`；配額為 0 要被遵守；負數配額拋 `ValueError`；
質心維度與池中向量不符時拋 `PaperPoolError`。

**關於輪替**：排序鍵讓推薦過的論文排到隊伍後方，等其他高分論文輪過一遍才再出現。
因此不會連續多天重複同一篇，但也沒有論文會被永久丟棄——只有寫成卡片才會被排除。

### 13. 分數與既有公式等價（`ScoreEquivalenceTests`）

分數 = `(論文向量 · 質心向量) × 10`。

這必須與 `src/zotero_arxiv_daily/reranker/base.py` 的做法
「對每篇閱讀紀錄各算餘弦相似度，依時間衰減權重加權平均，再乘以 10」**數值等價**，
因為內積是線性的：

$$\sum_i w_i (c \cdot h_i) = c \cdot \left(\sum_i w_i h_i\right)$$

用質心可少算 `len(history)` 倍的乘法，排序與分數皆不變。
時間衰減權重為 `1 / (1 + log10(rank + 1))` 正規化後的值，順序由新到舊，總和為 1。

## 測試品質要求

測試必須**真的能抓到錯誤**，不能只是走過流程。以下突變植入後，測試套件必須失敗：

| 植入的錯誤 | 應有的反應 |
|---|---|
| `normalize_title` 改成 `title.lower()` | 大量失敗 |
| `recommend_count = recommend_count + 1` 改成 `= 1` | 失敗 |
| `select()` 拿掉 `carded = 0` 過濾 | 失敗 |
| `ingest()` 拿掉 `norm_title` 去重 | 失敗 |
| `pending_embeddings()` 回傳全部列 | 失敗 |

其他要求：全部離線（不連網、不呼叫 API、不下載模型）；向量用固定亂數種子。

## 一般性檢查

- SQL 一律參數化，不得字串拼接
- 寫入操作要有交易邊界，中途失敗不留下半寫入狀態
- 例外不得被吞掉而讓資料靜默損壞

## 已知限制（屬預期行為，非缺陷）

- **IEEE 期刊論文抓不到全文**（付費牆），`full_text` 為 `None`，
  TLDR 會自動回退成摘要——這是既有的 `generate_tldr` 行為。
- **`論文總覽：PatchTST` 卡片比對不到任何論文**，因為它的 `來源論文：`
  指向 arXiv 查詢網址而非論文標題。`mark_carded()` 會回報它。修卡片即可解決。
- **只有 `abstract` 參與相似度計算**，`title` 不參與計分。
- 相似度採全部閱讀紀錄的加權平均（非 max 或 top-k），
  多主題閱讀紀錄會有質心稀釋效應——這是明確選擇的取捨。
